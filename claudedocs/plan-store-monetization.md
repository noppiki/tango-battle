# Plan: 単語バトル Store Monetization (Phase A-TB)

## Context
Target pivoted (2026-07-23) from EnglishWordGame to 単語バトル (`~/handoff`, repo noppiki/tango-battle, branch feature/modular-refactor). Proven assets to port from EnglishWordGame branch `feature/store-monetization`: Capacitor scaffold pattern, platform/entitlements/revenuecat modules (simulator-QA-passed), parental gate + purchase sheet UX, kids-category checklist, market research + pricing (単品¥800×3 / bundle ¥1,800, buy-once). User-approved model: free tier = 5級 (+future 6/7級); paid = 4級/3級/準2級; 選んだ級のみ出題; store build gated, web/PWA stays fully unlocked (unpromoted).

## Workstreams
1. **Graded word DB port**: transform EnglishWordGame's 1,466-word graded DB (en/ja/grade/difficulty) into tango-battle's schema. Schema change: `data/words.json` entries become 4-tuples `["word","意味","pos","grade"]` (grade ∈ g5|g4|g3|p2). Existing 933 entries (incl. all 熟語 pos=j) get `"p2"` — they were curated as Pre-2. Imported words need `pos` inference (v/n/a/d/c) — automated tagging + spot-check; dedupe by `word` (case-insensitive) against existing 933: on a duplicate, KEEP the existing entry's 表記/意味(ja)/pos but ADOPT the imported entry's `grade` (lowest-commonly-taught rule — the lower/earlier grade wins, e.g. existing p2 + imported g4 → g4); non-duplicated existing entries default to `p2` (熟語, pos=j, all stay p2 for now). Regenerate words.js via scripts/gen-words-js.mjs. **Validation gate (run during the port, findings included in the phase report)**: per-grade word counts before/after the merge; a list of every duplicate word with its grade transition (p2→gX); assert zero duplicate words remain in the final DB; assert every entry has a valid grade (g5|g4|g3|p2) and a valid pos; for every downgrading duplicate (p2→gX), manually spot-check that the KEPT existing 意味/pos still matches the sense the imported entry actually graded at gX (reject/flag mismatches from multi-sense or cross-pos collisions, e.g. imported basic-sense g5 vs. existing advanced-sense entry — do not silently downgrade a mismatched sense). Provenance comment: curriculum-aligned estimate, not official Eiken vocabulary (trademark-safe: never write 英検 in app code/UI — follow repo's existing naming convention, e.g. 級 labels as 5級/4級/3級/準2級 without 英検 prefix; verify how the app currently phrases "Pre-2 LEVEL" and stay consistent).
2. **Grade picker UI**: new seg control on home (matching existing `.seg` pattern) — 5級/4級/3級/準2級. Selection persisted in the settings storage (follow `eiken-p2-settings-v1` pattern via js/storage.js). Word pool for a battle is drawn at game start from the selected grade only (games are short one-shot sessions; pool frozen at start naturally). 熟語 filter interaction: 熟語 exist only at p2 initially — when a lower grade is selected, 出題はんい seg hides/disables 熟語 (report exact chosen behavior).
3. **Entitlement layer port**: new ES modules `js/platform.js`, `js/entitlements.js`, `js/revenuecat.js` — port logic from EnglishWordGame's IIFE versions (same provider boundary, localStorage cache for offline, MockProvider on web, product ids unlock_g4/g3/p2/all, entitlement ids grade_g4/g3/p2). Locked grades show a lock badge on the seg; tapping → lock explanation → 「保護者の方へ」→ arithmetic parental gate (3 tries, 60s cooldown) → purchase sheet — ALL restyled in the neon/pixel design language (existing tokens --p-child/--c-* etc., DotGothic16/Press Start 2P; no Mystic Library carryover).
4. **Capacitor scaffold**: package.json exists (esbuild) — add @capacitor/core+cli+ios+android + @revenuecat/purchases-capacitor. appId: trademark-safe, e.g. `com.noppiki.tangobattle` (confirm with user before store submission; changeable until then). webDir: reuse the existing single-file bundle approach OR a www/ rsync of the modular app — decide during implementation (modular app + relative paths is Capacitor-ready per CLAUDE.md; prefer www/ rsync of index.html+js+css+data+icons+img, skip sw.js registration on native).

**Fail-closed paywall boundary** (applies to workstreams 3 & 4): the native (store) build must be fail-closed — RevenueCat provider is the ONLY provider in the native bundle; if RC init/network fails, locked grades remain locked (only the persisted entitlement cache can unlock offline). MockProvider (the web-only dev/unlock path) must be EXCLUDED from the native www bundle at build time: the www build script produces a native variant that omits/strips the mock module (e.g. a separate entry point or a build flag), and an automated check (run in phase ④ and again before any store submission) asserts the native bundle contains no MockProvider identifier and no all-unlocked code path. The web PWA build keeps MockProvider all-unlocked as designed (unaffected).
5. **Kids-build network gating**: audit outbound calls — Google Fonts links (self-host DotGothic16/Press Start 2P subsets in the store build — pixel fonts are the identity, cannot fall back to system fonts), speechSynthesis (local, fine), any fetch of words.json (local, fine). RevenueCat traffic allowed as IAP mechanism (disclosed). No push/sync exists in this app — simpler than EnglishWordGame.
6. **RevenueCat**: create a NEW RC project for 単語バトル (own Test Store + API key in a new `js/store-config.js`), same product/entitlement ids as えいごの魔法 project so ported code is unchanged. Dashboard setup via browser (products ×4, entitlements ×3 with attachments) — same recipe as before.
7. **Tests/QA**: repo currently has no test framework — add minimal node-based unit tests only for pure logic (grade filtering, entitlement translation) runnable via `node --test` (no new heavy deps); simulator purchase-flow QA per agent-lessons-ios-sim-qa recipe.
8. **Production IAP pipeline (pre-submission)**: App Store Connect app record (final bundle id decided with user); create the 4 IAP products (non-consumable, ids matching unlock_g4/g3/p2/all) in ASC; connect the RC project's iOS app (bundle id + App Store Connect API key / shared secret); replace the Test Store key with the production `appl_` key in store-config for release builds; then device/TestFlight **Sandbox QA**: sandbox purchase, restore, offline entitlement, refund behavior smoke check. Same sequence later for Play (Google Play Console + `goog_` key). Store submission is blocked until Sandbox QA passes. Test Store remains for development only. Depends on the user's Apple Developer account.
